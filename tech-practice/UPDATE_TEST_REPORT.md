# 知习 0.4.0 软件更新测试

日期：2026-11-10。平台：Windows x64。开发目标：检测 Git 提交变化，在左下角显示可更新入口，同步并构建后重启切换，保留本地修改与个人学习数据。

## 后端与 Windows 安装助手

npm test 的 35 项全部通过，包含 25 项既有核心/学习测试和 10 项更新专项。更新专项使用临时本地 Git 普通仓库与 bare 仓库，真实执行提交查询、fetch、祖先判断和 fast-forward；未对个人工作区做测试性 reset 或强推。

覆盖：

- 版本号不变、提交改变时可发现更新；已是相同提交时显示最新。
- 同步后源码到达目标提交；构建文件在独立暂存目录，重启前旧程序仍保留。
- 已跟踪/未跟踪的个人修改、特性分支及历史分叉均阻止覆盖。
- 网络失败可重试，首选仓库不可达时回退备用源。
- 未保存编辑阻止更新；构建失败保留原打包程序。
- 安装目录边界、暂存/备份同级约束和程序完整性检查。
- 关联仓库拒绝无关目录；测试模式不联网。
- 实际 Node/npm 子进程执行 npm ci 和构建脚本；此项使用无外部依赖的小型构建夹具。
- 实际 Windows PowerShell 助手移动隔离程序目录并启动 C# 模拟 EXE；损坏新版 EXE 时恢复并启动旧 EXE。
- 构建过程中新增本地修改时停止安装，防止安装混合来源的构建。

首轮 Windows 助手暴露 PowerShell 5.1 对 UTF-8 无 BOM 中文字面量的解析问题；脚本改为 ASCII 后，正常切换和启动失败回滚均通过。

## 边界与交付

未让个人正在使用的程序在测试中更新自身。Git 同步、npm 子进程及目录切换通过分层隔离夹具验证；打包程序验证界面及原功能。没有宣称已执行真实用户数据上的无人值守整机更新或全量 RTL 仿真。

此功能依赖本地源码仓库及 Git、Node.js 24+、npm，并需要下载依赖的网络。阶段进度不是下载字节百分比。失败暂存和旧程序备份不自动删除。目录/进程启动回退不等于检测并回滚所有新版业务错误。详见仓库 docs/软件更新.md。
