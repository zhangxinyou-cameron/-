# 知习题库生成

交付能导入知习的题库文件，题干、答案、解析和测试应围绕用户的学习目标。默认兼容知习 0.1.0 的 QBank 1.0；软件支持与环境已经安装是两回事。技能自身不依赖刷题软件的安装目录。

## 先确定生成还是修复

- 新建：按用户给定资料、范围、题量、题型和难度出题；不要把内置示例的知识范围当作用户要求。
- 修复：读取原题库和报错，保留未受影响题目、稳定 ID、题意及已有测试；修复格式不能靠删题、删测试或放宽判分蒙混通过。
- 增量更新：读取用户提供的已发布版本，保持 bank_id 与原题目 ID；新增题目用新 ID。任何已发布题目字段或引用文件改变，都递增该题 revision；题库发布变更也递增 bank_version。
- 用户需要复制给其他 AI 的提示词时，读取 [prompt-templates.md](references/prompt-templates.md)，按当前任务填好内容后交付；不要只返回未填写的模板。

用户已经说明的条件直接采用。题量、难度未指定时，可先做 10 道基础到进阶的小题库，并简短说明默认范围。只追问会影响答案或执行协议的缺失前提；其余常规选择自行完成。

## 选择当前软件能处理的内容

默认使用 single_choice、multiple_choice、true_false、code、rtl。fill_blank 与 short_answer 只有用户明确需要时才生成，并说明初版只支持阅读、解析和笔记。

编程或 RTL 题读取 [runtime-profiles.md](references/runtime-profiles.md)，确定语言、接口和评测合同。当前自动评测环境 ID 仅有：

- python-stdio-1：完整 Python 程序、标准输入输出。
- c11-stdio-1 / cpp17-stdio-1：完整 C11 / C++17 程序、标准输入输出。
- iverilog-verilog-1：基础 Verilog-2005 模块与自检查 testbench。

不要把 Java、Rust、Go、完整 SystemVerilog/UVM 等需求偷偷换成上述语言，也不要虚构环境 ID 已经可用。可提供相关客观题，或按用户选择交付标明暂不可运行的扩展题库。没有环境信息时，列出所需能力，不假设用户已安装编译器或仿真器。

## 组织题目并写入协议

读取 [protocol.md](references/protocol.md) 与 [qbank.schema.json](references/qbank.schema.json)。只在需要结构参考时读取 [完整示例](assets/example-bank.json)；只做客观题可先看 [最小题库](assets/minimal-bank.json)。

先安排知识点覆盖、题型与难度，再生成题目。解析应把正确原因、错误选项及适用前提讲清；避免同一知识点的纯换词重复题。来源记录真实出处，不知道时明确原创或未核实，不补造链接、页码、授权或“已验证”状态。

默认生成一个完整 UTF-8 .json 文件，代码和 testbench 作为 files 中的 inline content，用户无需另外拼接代码文件。存在图片或其他二进制附件时才生成 .qbank.zip，根目录含 bank.json，附件摘要按实际文件计算。

对于执行题，题干先固定数据范围、边界、输入输出或硬件接口，再分别编写参考解和独立测试。至少覆盖普通情况与真正能区分错误解的边界；不要只用题干样例判分。测试输入不符合题目保证时，不应拿它判学习者答错。

## 校验与修正

写文件后运行随技能附带的校验器。它复用了知习初版的结构与语义校验，再检查当前版本兼容性和已发布版本冲突；**不会执行题库中的代码、导入软件或安装环境**。

```text
node <skill目录>/scripts/validate_qbank.cjs <题库.json或.qbank.zip> --report <校验报告.json>
```

更新已发布题库时添加 `--previous <原题库文件>`。用户明确需要预留题型或未实现环境时用 `--profile schema`，同时保留“不支持自动评测”的提示；不能用该选项绕过结构、引用或版本错误。

使用现有 Node.js 18+，也可以使用可用工具提供的 Node 运行时；校验依赖已经打包，不需要 npm install。协议与校验器版本指纹见 [validator-profile.json](references/validator-profile.json)。脚本退出码：0 为检查通过，1 为题库不符合要求，2 为命令或资源错误。根据报告中的 code、json_path 和 question_id 修复后重跑。结构正确不等于知识正确。

随后审查题意、答案唯一性、解释、参考解和测试。若已有适用工具且可在当前授权与隔离条件下运行，检查参考解通过全部测试，并用至少一个有针对性的错误解检查测试是否能识别错误。缺少工具时如实标注未运行，不为了完成出题任务自动下载安装或执行外来环境脚本。

RTL 要核对复位、位宽、采样时序、X/Z 语义、检查点数和结束标志；细则见运行环境参考。功能仿真通过不能替代 STA、CDC、综合或物理实现验证。

## 交付方式

用户要文件时，交付题库文件及简短说明：题量、题型、知识范围、所需环境、结构校验结果，以及参考解实际运行或未运行的范围。必要时附机器可读校验报告。质量状态放在报告里，不向 schema 未定义位置塞字段。

用户明确要求只输出 JSON 时，只返回完整 JSON 对象，不加围栏、注释或前后解释；在回复前完成可行的校验。不要声称未执行的检查已经通过。

内容过多时拆成完整的小批题库，保持稳定 ID 且不重复出题；不能用省略号或半个 JSON 充当交付。用户只要求生成文件时，不自动改动软件数据库、安装配置或其他现有题库。
