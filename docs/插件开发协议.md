# 知习插件 API 1

当前为随应用构建的可信注册式插件，不支持下载任意 JS/ZIP 后热安装或进程沙箱。后续功能应独立成模块，通过插件管理开启/关闭。现有刷题基础能力继续作为核心。

## 后端

在 tech-practice/desktop/plugins/ 下新增模块，导出 manifest 和同步 activate(context)。manifest 含唯一小写 id、name、version、apiVersion:1、description、defaultEnabled。context 当前提供 store 与 validator，不能从插件假设拥有窗口、shell、任意安装或账户凭据接口。

activate 返回 {handlers:{action(payload){...}}, dispose(){...}}。在 desktop/plugins/index.mjs 的默认定义数组注册模块。宿主按需调用 activate，仅调用自身 handlers 中已注册的 action；关闭后阻止调用并 dispose，重启后保留开关。dispose 要释放计时器和监听，不删除个人数据。激活异常记录在插件管理中，不使其他插件和核心启动失败；关闭再开启可重试。

数据使用 meta 中带插件前缀的 key，例如 plugin:my-plugin:record:ID；开关由宿主管理 plugin-enabled:ID。复杂功能也可用独立表，但需兼容老数据库与已有备份。只通过 store.transaction 执行同步写操作。嵌套事务加入最外层事务，异常须向外传播，不在事务中 await，不直接写数据库文件。

用户通过 renderer 的 api('plugin',{id,action,payload}) 调用。插件开关 api('togglePlugin',{id,enabled})；清单随 bootstrap.plugins 返回，并可用 api('plugins') 刷新。不要新增任意动态 import、任意 SQL IPC 或传入脚本执行入口。

## 前端

组件放在 src/plugins/，并在 src/plugins/index.ts 的 pluginViews 中按 id 注册。主框架根据 manifest 及开关生成导航、渲染页面，不需要给每个插件重写核心页面切换。

需要阅读或编辑 Markdown 时复用 components.Markdown（marked + DOMPurify）；不得直接插入不受信任的 HTML。关闭插件后组件卸载。产生未保存内容的插件须通过 pluginDirty/confirmNavigation 通知宿主；离开页面或关闭程序时有保存/放弃的明确选择。学习插件作为完整参考，使用显式保存，不声称未落盘的文本已保存。

## 验证

每个插件至少检查：注册与重复 ID、开关接口拦截、重启状态、dispose 释放、无效 payload、持久化及备份恢复。数据导入检查稳定身份、版本冲突与原子性。测试激活失败不会拖垮其他功能。

学习功能额外检查阅读/独立通过两个条件、辅助通过不算闭环、修改正文后重新阅读、升级保留笔记、导出不带个人笔记、题目缺失提示、文本 HTML 清洗、真实章节测试导航。

运行 npm test（核心+插件），npm run test:learning（学习桌面流程），npm run test:ui（既有桌面流程），npm run test:startup，以及 npm run build。按本次变动选择相关范围，失败修正后再重跑；不把未执行项写成通过。
