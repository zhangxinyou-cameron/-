# 个人技术刷题软件功能设计文档

版本 1.0　日期 2026年10月27日　用途 产品评审与开发拆分

本软件服务于个人长期学习数字 IC、编程语言和其他软硬件技术。核心使用方式是：按学习目标让 AI 生成结构化题库，软件校验导入后提供做题、代码运行、判分、解析、错题复习和学习统计。题库与学习记录保存在本地，关闭 AI 服务后，已经导入的内容和已经配置的代码环境仍可使用。

建议先交付 Windows 桌面版本，首版打通选择题、判断题、Python 和 C/C++ 编程题、基础 Verilog RTL 题的完整流程。题库协议与运行器采用可扩展设计，逐步加入其他语言、SystemVerilog 验证、波形查看、主观题辅助评价和更复杂的实验。软件不以账号、社区或竞赛排名为首版目标。

本文的 P0 表示首个可用版本必须具备，P1 表示核心流程稳定后的增强版本，P2 表示后续扩展。文中性能数字、评分规则和技术选型是本产品的设计目标，需在实现时验证，并非对现有实现的描述。

## 1 产品定位与使用边界

### 1.1 目标用户与核心价值

目标用户既是学习者，也是个人题库维护者。日常需求包括补基础、练代码、学习 RTL、准备技术面试、定向复习工作中接触的新知识，以及整理错误和笔记。

软件需要让学习内容与软件版本解耦。新增“Python 生成器”“数字电路时序分析”“C 指针”等内容时，只需新增题库；新增尚未支持的语言或评测方式时，需要增加运行器，不能仅凭一段题目描述获得执行能力。

完整学习流程为：

学习目标 → AI 或人工整理题库 → 格式与质量检查 → 导入预览 → 练习或测验 → 判分与解释 → 错题和笔记 → 到期复习 → 调整学习计划。

### 1.2 首版默认假设

- 单用户、本地优先、中文界面；题目与代码允许英文。
- Windows 10/11 作为首要适配平台，实际支持的系统版本由打包测试确定。
- AI 可在软件外部使用，复制 JSON 或导入文件即可，不强制绑定某个模型供应商。
- 编程界面内置编辑器和运行入口；解释器、编译器、仿真器作为独立运行环境管理。
- 普通做题可完全离线。首次安装运行环境、下载依赖和调用远程 AI 时可能需要网络。
- 允许导入原创、个人整理及有使用权限的内容；题目保留来源和版本信息。

### 1.3 首版范围

| 能力 | P0 首版 | 后续版本 |
| --- | --- | --- |
| 客观题 | 单选、多选、判断，自动判分 | 填空、排序、匹配和结构化计算题 |
| 软件编程 | Python、C、C++，标准输入输出题 | 函数签名题、多文件项目及更多语言 |
| 硬件练习 | Verilog 基础 RTL，固定 testbench 仿真 | 波形内嵌、更多 SV 特性、验证和综合任务 |
| 题库管理 | JSON 与题库包导入、校验、编辑、版本管理 | 大题库流式导入、其他格式转换 |
| 学习闭环 | 专题练习、错题、收藏、笔记、复习、统计 | 自适应推荐、知识图谱与综合实验 |
| 环境管理 | 探测、可信预设安装、检查、固定版本 | AI 自定义环境脚本包与高级运行器插件 |
| AI | 软件外生成题库，导入及修正反馈 | 软件内生成、提示、辅助评分与追问 |
| 数据管理 | 自动备份、导出、恢复 | 多设备同步与冲突处理 |

协议可提前定义 P1 题型。首版导入到这些题型时保留内容并显示“暂不支持作答”，不得直接报成题目错误；首版实际验收以 P0 清单为准。

## 3 信息架构与主要页面

### 3.1 一级导航

1. 今日学习：继续上次练习、到期复习、今日目标、最近题库。
2. 题库：目录、筛选、搜索、导入、编辑、导出、版本。
3. 专题与计划：学习路径、章节、任务和进度。
4. 错题与复习：待复习、已纠正、薄弱知识点。
5. 收藏与笔记：收藏集合、个人笔记、代码片段。
6. 学习统计：有效练习、首次正确率、独立通过率和复习情况。
7. 运行环境：已安装环境、缺失环境、安装队列和诊断。
8. 设置与备份：界面、快捷键、数据目录、AI 连接、备份恢复。

### 3.2 题库列表

题库卡片显示名称、知识领域、题目数、已练习数、掌握状态、待复习数、内容版本及质量状态。题目列表支持按领域、章节、知识点、题型、难度、作答状态、环境可用性和质量标记组合筛选；支持按题号、名称、题干和标签搜索。

领域使用稳定 ID，如 digital_ic、programming、computer_architecture、embedded；目录允许用户自建。题目可属于多个知识点，但有一个主知识点，防止统计重复累计题数。

### 3.3 作答工作台

桌面默认双栏：左侧为题干、约束、样例、提示、来源和笔记入口；右侧为选项或代码编辑器。底部按需展开样例输入、输出差异、编译日志、测试结果和仿真产物。

顶部显示题库、题号、难度、知识点、当前环境、练习模式和计时。底部操作包括上一题、下一题、标记稍后、收藏、提交、查看解析；编程题另有运行和停止。窄窗口可切换单栏，代码区域支持全屏、字号、缩进、暗色主题和常用快捷键。

每题草稿按题目版本与语言分别保存，输入后 1 秒内触发增量保存，失焦和退出时强制保存。切换题目不丢代码；重置模板前展示即将覆盖的草稿并提供撤销。作答过程不要求持续联网。

### 3.4 反馈区域

反馈必须分清三层：本次结果是什么、根据什么判定、下一步可以做什么。例如“第 7 个边界用例未通过：空输入应返回 0，你的程序返回空行”；RTL 示例为“复位释放后的第 3 个上升沿，count 期望 2，实际为 X”。

运行环境缺失应显示“未判分，去配置环境”；测试包损坏应显示“题目测试错误，待检查”；AI 反馈单独标注“辅助建议”。不能把这些情况归为学习者答错。

## 4 题型与评分规则

### 4.1 客观题

| 题型 ID | 输入形式 | 默认判分 | 必须提供的反馈 |
| --- | --- | --- | --- |
| single_choice | 选择一个选项 | 选项 ID 相等才正确 | 正确选项、逐项说明、相关知识点 |
| multiple_choice | 选择多个选项 | 集合完全相等才正确 | 漏选、多选和正确集合 |
| true_false | 是或否 | 布尔值一致才正确 | 正确结论及适用前提 |
| fill_blank | 一个或多个空 | 各空按规则匹配，按空给分 | 标准答案、容许形式和错误位置 |
| short_answer | 文本或 Markdown | 自评；可选 AI 量表辅助 | 参考要点、分项建议、评价来源 |

P0 多选题只采用全对得分，避免不同题库评分不一致；P1 若增加部分得分，题目必须声明规则且选错项不得获满分。选项使用稳定 ID，如 opt_a；显示时可以打乱顺序，但判分必须按 ID。未选不能等同于判断题的 false。

填空默认去除首尾空白，不默认忽略大小写、不默认替换标点。每空可声明候选答案、大小写规则；数值题以后增加单位及绝对/相对容差，不能用字符串匹配假装数值评测。用户来源的正则不作为首版评分能力。

主观题在尚未接入 AI 时仍可对照要点自评。AI 评分保留模型、评价时间、量表版本和分项解释，结果标记 ai_assisted，不进入“客观正确率”；用户可以修改自评，不得改写原始评价记录。

### 4.2 软件编程题

P0 采用完整程序的标准输入输出协议，语言由 runtime_ref 声明。题目包含输入输出说明、数据范围、样例、起始代码、参考解答、测试集和资源限制。C/C++ 需明确语言标准，Python 需固定解释器环境。

“运行”执行样例或用户输入，结果为调试记录；“提交”执行正式测试集并生成正式作答记录。样例通过只显示“样例通过”，只有正式测试集全部通过才显示“测试通过”。编译成功本身不能代表答对。

测试默认逐用例启动干净进程，输入为 UTF-8 字符串，运行器关闭 stdin 后等待输出。默认比较规则为 trim_end：统一 CRLF 为 LF，仅去除输出整体末尾空白；不删除中间空格、不排序。exact 只统一换行，其他字符必须一致。float_tokens 留作 P1，容差必须写入题目。

首版整体通过条件为全部用例通过；分数为 100 × 通过用例数 ÷ 全部用例数，保留两位小数，不能把部分通过记为通过。客观题每题默认满分 1 分；主观题使用量表 max_score。P1 可加入测试组权重及子任务，修改后需升级题目 revision。

### 4.3 RTL 与数字 IC 题

RTL 题除共同字段外，必须明确：顶层模块名、端口名、方向、位宽、时钟采样沿、复位极性和同步/异步属性、有效延迟、参数范围、时序单位、起始代码、参考 RTL、testbench 与仿真器能力要求。

P0 覆盖组合逻辑、寄存器、计数器、移位寄存器、简单 FSM、同步 FIFO 的基础行为。每题声明检查维度；默认只判功能仿真。功能通过、静态告警、综合结果和时序结果分别呈现，不能由 RTL 仿真通过推断实现满足芯片时序、面积、功耗或 CDC 要求。

testbench 应独立计算期望结果，覆盖正常输入、边界、复位、保持及连续操作。时序题需避免在同一事件队列中制造采样竞态；明确在时钟沿后何时采样。涉及 X/Z 或三态语义的题目必须使用对应四态能力环境，不能无提示换用不等价的两态评测。

RTL 提交结果包括编译状态、断言或检查点通过数、首个失败时间、信号期望值与实际值、随机种子，以及可用的 VCD/FST 等产物。首版支持下载波形及用外部查看器打开；P1 内置波形查看器，支持信号树、游标、时钟沿定位、缩放和失败点跳转。

用于判分的 testbench、参考文件和预期结果不在普通编辑器中可写。用户自己编写 testbench 属于 P1 验证题，需要另一个可信评测器检查其能否识别注入缺陷；不能只看用户输出 PASS 就给分。纯本地个人软件不承诺防作弊或对题库答案的强保密。

### 4.4 评测状态

| 状态 | 含义 | 对学习统计的影响 |
| --- | --- | --- |
| AC | 当前题目版本的正式测试全部通过 | 一次有效通过 |
| WA | 输出或功能检查不符 | 一次有效未通过 |
| CE | 用户代码编译错误 | 一次有效未通过，记录错误类别 |
| RE | 用户程序非正常结束 | 一次有效未通过 |
| TLE | 用户程序运行超时 | 一次有效未通过 |
| MLE | 用户程序超出内存限制 | 一次有效未通过 |
| OLE | 输出超过限制 | 一次有效未通过 |
| ENV_ERROR | 环境缺失或能力不满足 | 不计对错，保留诊断 |
| JUDGE_ERROR | 题库测试、适配器或评测系统故障 | 不计对错，可重试 |
| CANCELED | 用户取消或恢复后发现任务中断 | 不计对错 |

若无法确定故障属于用户代码还是系统，应优先返回 JUDGE_ERROR 并保留日志，不能猜测为 WA。编译失败要区分用户语法错误与工具缺失；运行器超时也要区分编译、用例执行和基础设施启动。

## 5 日常练习与学习管理

### 5.1 练习模式

- 顺序练习：按题库或章节顺序继续，可跳过并返回。
- 随机练习：按筛选条件抽题，排除本轮重复题，支持固定随机种子重现。
- 专题练习：围绕一个或多个知识点，支持先修章节提示。
- 错题练习：按错因、未纠正状态或到期时间抽题。
- 每日任务：由到期复习和少量新题组成，可手动调整。
- 模拟测验 P1：限定题量、范围、时间；统一交卷后看解析，支持中断恢复和超时交卷。

练习模式可立即看反馈；测验模式提交单题后不泄露正确答案。显示顺序、随机种子和题目版本在练习会话中固定，续做时不重新抽题。

### 5.2 错题与错因

有效提交未通过时自动加入错题本，保留原始答案、代码、题目快照、结果与时间。客观题记录漏选/多选/概念混淆；编程题记录边界遗漏、语法、算法、位宽、符号、复位、时序等可编辑错因。系统推断的错因需显示来源，用户可以修改标签。

以后通过不会删除旧记录。错题本展示“待纠正”“已纠正待复习”“复习稳定”三个业务状态，支持手动移出与撤销；移出不删除作答历史。

### 5.3 复习与掌握状态

首版采用透明规则：出错后安排约 10 分钟的短复习；独立通过后按 1、3、7、14、30 天逐级安排，到 30 天级后保持该间隔。任一次复习失败回到短复习。用户可以调整间隔或暂停某题，界面显示下次复习时间与原因。

同日反复提交仅能纠错，不得连续提高多个复习等级。使用提示、看答案后完成标记为 assisted，下一次安排短复习且不增加独立掌握等级。若累计多日逾期，保留到期队列，不把所有逾期记录伪装成当天新增任务。

掌握状态按题目版本记录：未学、学习中、待复习、暂时掌握。默认“暂时掌握”要求至少两次独立正确且跨两个本地自然日，并通过至少一次到期复习。题目改题干、答案或测试后重置当前 revision 的掌握判断，旧版记录仍可查询。

P1 可采用经验证的 FSRS 实现，迁移前备份，保留评分历史与调度算法版本；不能仅把固定间隔改名为 FSRS。编程题掌握还受变式和综合运用影响，页面不将记住一道题的答案等同于掌握整个知识领域。

### 5.4 计划与专题

用户可创建“4 周数字 IC 基础”“C/C++ 指针专题”等计划，设置学习范围、每日新题数、复习上限和目标日期。章节支持先修关系，检测循环依赖；没有先修信息时允许自由练习。

任务完成依据明确：阅读笔记、完成题量、独立通过某题或完成复习。未完成任务可以顺延，用户可暂停计划。P1 根据有效作答和薄弱点给出建议，新增题库时只建议纳入，避免静默改变既定计划。

### 5.5 收藏与笔记

支持多个收藏夹、题目笔记和知识点笔记。Markdown 笔记支持代码、公式、图片、双向题目链接和全文搜索；笔记是用户数据，题库更新不得覆盖。可将一次失败的代码、波形截图或关键解析附到笔记中，导出时带题号与版本。

### 5.6 学习统计口径

按日、周、月及知识点显示新学题数、独立通过题数、到期复习完成率、有效学习时间、错因分布和趋势。统计可点击回到支撑记录。

首次正确率 = 首次正式作答正确的客观题数 ÷ 有有效首次正式作答的客观题数。编程独立通过率 = 在选定统计周期首次完成独立正式通过的不同题目数 ÷ 同周期有有效正式提交的不同编程题目数。题目按稳定身份去重，revision 明细可下钻；查看答案或使用提示后通过不计独立通过。

调试运行、取消、环境故障和重复点击均不增加有效题量。日统计按用户时区划分，存储使用 UTC；默认时区 Asia/Shanghai。学习计时在窗口失焦或连续 5 分钟无输入时暂停，可手动修改；界面说明计时是近似值，不用于评价能力。

## 6 AI 与题库质量

### 6.1 外部 AI 导入流程

用户在软件中选择领域、章节、知识点、题型比例、难度、题量和目标运行环境，导出“出题提示词 + 协议版本 + schema + 可用环境摘要”。把 AI 返回的 JSON 粘贴或导入文件后，进入预览、校验、修正和发布流程。

首版无需内置模型即可完成上述流程。软件应能导出机器可读错误清单，用户可以连同原始 JSON 交给 AI 修复；修复后的内容仍需重新校验。

### 6.2 软件内 AI 能力 P1

可选接入远程模型或本地模型，按连接配置能力、上下文上限、超时和费用提示。支持按上传的学习资料出题、解释错因、生成渐进提示、生成变式题，以及将重复错误整理成知识卡片。

AI 提示分三级：方向提示、局部思路、完整参考答案。点击后记录使用级别。默认提交前不自动展示完整答案，不让助手替用户自动提交代码。发送前可查看将上传的题目、答案、代码和日志，默认不发送其他题库、API Key、本地路径和无关笔记。

生成、评审、正式题库三者分离。AI 输出先进入草稿区；任何 AI 操作均不得未经用户选择直接覆盖正式题目、作答历史或执行系统命令。API Key 放入操作系统凭据存储，备份和日志默认不包含密钥。

### 6.3 题库质量状态

质量状态为 draft、validated、verified、disputed、retired。draft 为尚未校验；validated 表示结构、引用和基本规则通过；verified 表示参考解通过测试且客观题已有人工确认或独立复核；disputed 表示被标记存在争议；retired 表示不再用于新练习。

这些状态由软件维护，导入文件不能仅凭自报 verified 就获得可信状态。AI 生成的内容默认标记“AI 生成，待复核”。schema 通过只证明结构合法，不证明知识正确、答案唯一或测试充分。

编程题发布前需运行参考解；至少还要放入一个已知错误解，确认测试能够拒绝它，并提示补充边界测试。参考解与测试同由 AI 生成时，存在同源错误风险，重要题目需独立核对。无来源的题目可以导入，但来源状态必须明确。

## 7 题库协议 QBank 1.0

### 7.1 文件形式

小型题库使用 UTF-8 编码的 .json，单个文件含元数据、知识点、题目和内联文本文件。AI 可直接输出该 JSON，不要求用户手动把多段代码拼成目录。大型题库使用 .qbank.zip，包含 bank.json、assets/ 和 files/；bank.json 的结构相同，文件内容可改用题库包内路径引用。

本次随附的 qbank.schema.json 定义 1.0 的 JSON 结构，示例题库覆盖 7 种题型。首版软件只需实现 P0 的五种类型；fill_blank 和 short_answer 是预留能力，导入时提示不支持即可。

题库不得包含必须联网执行的内容。Markdown 中本地资源使用题库相对路径，默认不加载远程图片；HTML、脚本和危险链接必须过滤。附件路径统一使用 /，不得为绝对路径、含 ..、盘符或反斜杠。

### 7.2 共同字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| schema_version | string | 是 | 固定为 1.0，未知主版本拒绝 |
| bank_id | string | 是 | 题库稳定 ID，改名不改变 ID |
| bank_version | string | 是 | 题库内容语义版本，如 1.0.0 |
| title / description | string | 是 | 名称与用途 |
| locale | string | 是 | 内容语言，如 zh-CN |
| authors / license | array / string | 是 | 作者与使用说明；不能凭空声明他人内容授权 |
| knowledge_points | array | 是 | ID、名称和可选 parent_id |
| questions | array | 是 | 题目记录，不得出现相同 ID |
| files | object | 是 | 相对路径到文件记录的映射，无附件时为 {} |
| extensions | object | 否 | 显式扩展字段命名空间，避免错拼字段被忽略 |

题目共同字段为 id、revision、type、title、domain、knowledge_point_ids、primary_knowledge_point_id、difficulty、estimated_minutes、stem_md、explanation_md、hints、sources。difficulty 为 1 至 5 的整数；1 表示入门，3 表示需要综合运用，5 表示较复杂的专项问题。

题目稳定身份为 bank_id + question.id；同一题的 revision 从 1 单调递增。bank_version 表示整库发布版本，不能替代逐题 revision。题目删除采用 retired 状态，学习记录按快照继续可读。

sources 的每条记录含 title、locator 和 note。locator 可以是网址、教材页码或“原创，未提供外部来源”，不要求伪造链接。导入器不把来源网页中的文字当作命令。

### 7.3 题型字段

| 题型 | answer 或 rubric | execution |
| --- | --- | --- |
| single_choice | options 与 correct_option_id | 不允许 |
| multiple_choice | options 与 correct_option_ids | 不允许 |
| true_false | correct 为布尔值 | 不允许 |
| fill_blank | blanks 含 id、accepted_answers、case_sensitive | 不允许 |
| short_answer | criteria 含要点和分值，max_score | 不允许 |
| code | 不允许静态 answer | runtime_ref、entry_file、starter_files、reference_files、limits、judge |
| rtl | 不允许静态 answer | 同上，另含 rtl_spec 与 hdl_testbench |

code 的 judge.kind 固定 stdio，含 comparator 与 tests。每条 tests 有 id、visibility、stdin、expected_stdout；visibility 为 sample 或 private。private 仅表示练习界面提交前不展示，并非加密，也不构成强保密。

rtl 的 judge.kind 固定 hdl_testbench，含 testbench_files、top_module、check_count。参考解和 testbench 都作为 files 中的文本文件记录。所有可执行内容只有在明确运行、提交或发布自检时才执行，导入和预览不能运行它们。

### 7.4 文件与运行环境引用

files 每项采用二选一形式：inline 提供 content；asset 提供 package_path 和 sha256。记录还包括 role，枚举为 starter、reference、test、asset。小题库优先 inline，图片、较大测试数据和波形素材使用 asset。sha256 校验文件一致性，不能代替来源可信判断。

starter_files、reference_files 和 testbench_files 都是 {source_path, target_path} 映射列表。source_path 是 files 的键；target_path 是任务目录内的相对路径。执行用户代码时加载 starter 映射并以草稿替换其中的可编辑文件；执行参考解时改用 reference 映射，两者不同时加载。entry_file 指向对应工作区中的入口，例如 main.py。RTL 的 testbench 映射在两种执行方式中都加载，且不可与当前代码映射的目标路径冲突。

runtime_ref 引用软件中已登记的版本化环境能力，例如 python-stdio-1、cpp17-stdio-1、iverilog-verilog-1。题库仅引用能力，不带任意宿主机启动命令。环境登记记录解析到具体工具版本、容器镜像摘要或本地可执行文件；实际版本锁由软件保存。

一个 execution 对应一个可判分环境；同题跨语言使用同一题目 ID 的语言变体是 P1 协议扩展，P0 可以用不同题目并用 extensions.related_question_ids 关联。不要在 1.0 中使用未定义的 languages 字段冒充已经支持。

### 7.5 导入阶段与错误报告

1. 解包预检：识别文件类型、编码与大小；拒绝路径穿越、符号链接、重复 ZIP 路径及异常压缩比。
2. 结构校验：按 schema 检查字段、类型、必填项和枚举，检测 JSON 重复键。
3. 语义校验：检查 ID 唯一性、引用、评分一致性、文件角色和题型能力。
4. 差异预览：新增、未变、更高 revision、冲突、缺失附件、缺少环境、暂不支持题型分别展示。
5. 原子导入：用户确认本次导入范围后用数据库事务与文件暂存提交，失败恢复原状。
6. 可选发布检查：显式运行参考解、已知错误解与测试包，记录质量报告。

结构或语义硬错误默认阻止整批提交。用户可选择“仅导入有效题目”，软件需生成新批次清单，明确排除的题号；不能静默漏题。环境缺失是软阻塞：可先导入、阅读和做客观题，编程题标记待配置。

错误报告提供 severity、code、json_path、question_id、message、suggested_fix。例如 E_OPTION_REF、$.questions[0].answer.correct_option_id、“opt_c 不在本题 options 中，请修正答案 ID”。程序化错误报告可导出为 JSON。

### 7.6 更新和冲突规则

同身份、同 revision、相同内容 hash 为幂等跳过；同身份、同 revision、不同内容为冲突，禁止直接覆盖；更高 revision 显示差异后更新并保留旧版；较低 revision 默认跳过，可另存为派生题库。题库包中未出现的旧题不自动删除。

内容 hash 使用去除无关序列化空白后的规范化业务 JSON，并纳入引用文件摘要。个人笔记、收藏和作答历史不参与内容 hash。题库和题目 ID 碰撞时可导入为新 bank_id，但要保存来源映射。

### 7.7 结构与语义校验分工

JSON Schema 检查结构；下列规则必须由导入器额外实现，不能误以为 schema 自动完成：

- 题号、知识点 ID、选项 ID、用例 ID、填空 ID 唯一。
- 所有知识点、正确选项和文件引用存在；主知识点属于该题知识点集合。
- 知识点 parent_id 存在且不构成环。
- 单选恰好一个答案；多选答案无重复且是选项子集；判断值为布尔值。
- 填空占位符形如 {{blank_id}}，与 blanks 一一对应；主观题要点分数之和等于 max_score。
- starter_files、reference_files、testbench_files 的角色分别匹配；入口位于起始与参考映射的目标路径列表；各次执行加载的文件目标路径无冲突。
- 软件编程题至少一个 sample 和一个 private 用例；RTL 需至少一个测试文件且 check_count 大于 0。
- 所有资源路径经规范化后仍在题库内；禁止 . 与 .. 路径段、Windows 保留设备名及尾部空格/点；按目标系统检测大小写和 Unicode 规范化后的路径碰撞。asset 只允许题库包内已存在、摘要一致的文件。
- 题目要求的能力与 runtime_ref 登记能力兼容；不兼容时禁止正式评测，保留内容并说明原因。

## 8 内置代码环境与运行器

### 8.1 用户体验

首次打开编程题时，软件展示“当前环境可用”或“需要配置某环境”。可用时一键运行；缺失时打开配置页，显示所需工具、预计下载和磁盘占用、安装位置、是否需要管理员权限、是否需要重启。完成后自动执行独立健康检查，并返回原题恢复草稿。

内置编辑器提供语法高亮、基础补全、搜索替换、多文件标签、括号匹配、错误位置跳转与代码格式化入口。补全和语言服务器按环境可选安装。P0 不要求完整 IDE 或断点调试；P1 增加受适配器支持的断点、变量查看和单步调试。

### 8.2 环境规划

| 环境能力 | 推荐用途 | P0/P1 | 边界 |
| --- | --- | --- | --- |
| python-stdio-1 | Python 基础与算法题 | P0 | 固定解释器，依赖按环境锁定 |
| c11-stdio-1 / cpp17-stdio-1 | C/C++ 基础与算法题 | P0 | 固定编译器、标准和编译选项 |
| iverilog-verilog-1 | 基础 Verilog 四态 RTL 仿真 | P0 | 只承诺已回归的语言特性 |
| verilator-sv-1 | 适合该工具语义的 SV 与较大 RTL 任务 | P1 | 不能默认替代四态仿真 |
| java/js/ts/rust/go 等 | 新语言学习 | P1 | 每种语言单独实现和回归适配器 |
| 商用 EDA 适配器 | 有许可证的专业实验 | P2 | 用户提供合法环境，不自动获得许可证 |

Icarus Verilog 的 SystemVerilog 支持有边界；Verilator 官方文档也列明语言限制和主要为两态的模拟语义，因此不能笼统承诺“所有 SystemVerilog/UVM 代码都可运行”。具体能力以安装版本的探测和题库回归结果为准。[Icarus 支持限制](https://github.com/steveicarus/iverilog/blob/master/README.md)、[Verilator 语言支持](https://verilator.org/guide/latest/languages.html)。

### 8.3 执行后端

推荐提供两种后端，统一经过 Runner API。容器后端是执行外来测试包的默认方式；没有可用容器后端时仍可做客观题，并引导配置后端。原生进程后端仅用于用户明确选择信任的个人代码与题库，界面显示其隔离能力有限。

Windows 可通过可用的 Linux 容器运行环境承载工具链，必要时引导配置 WSL2。WSL 本身不被视为完整安全沙箱。首次安装可能需要系统权限和重启；软件保存安装进度，不能宣称任何机器上都能完全无交互完成。

容器运行时使用非特权用户、禁用任务网络、只读根文件系统、仅任务目录可写、CPU/内存/进程数限制、输出和磁盘配额，不挂载宿主机用户目录、凭据、容器管理 socket 或系统根目录。容量限制要显式设置，Docker 默认不自动限制全部资源。[Docker 资源限制](https://docs.docker.com/engine/containers/resource_constraints/)、[Docker 安全说明](https://docs.docker.com/engine/security/)。

### 8.4 任务生命周期

queued → preparing → compiling → running → judging → finished。失败、超时和取消都是明确终态。默认并发一个正式任务；新任务可以排队，禁止重复点击产生相同提交。可取消整个进程树或容器，应用重启后检查未结束任务，标记中断并允许重试。

每次提交保存代码快照、题目 revision、参考文件与测试摘要、适配器版本、环境锁、编译选项、随机种子和结果。重跑使用相同锁；旧环境不存在时说明无法原样复现，不悄悄替换成新版本。

### 8.5 Runner API 合同

适配器提供 describe、probe、prepare、run、cancel 和 collect_artifacts。describe 声明支持的语言与功能；probe 返回实际版本及能力；prepare 创建工作目录；run 消费结构化请求并返回结果；cancel 终止任务；collect_artifacts 只收集允许的产物。

请求最少包含 protocol_version、job_id、attempt_id、question_revision、runtime_lock_id、adapter_id、mode、文件摘要与映射、评测配置和 limits。mode 为 sample 或 submit。传入程序与参数使用 argv 数组，不通过拼接 shell 命令执行；题库无权传入任意宿主机 executable。

结果最少包含 job_id、status、score、max_score、compile、case_results、usage、artifacts 和 diagnostics。case_results 含 case_id、状态、耗时、期望/实际摘要与可见性；usage 记录测量口径。原生日志与协议结果分流，不能解析用户 stdout 中的“AC”字符串作为最终结论。

输出是有上限的流式日志；超出 stdout/stderr 配额时保留截断标记并终止任务。RTL testbench 的结果由可信适配器验证检查数、结束标志与退出状态；如果只退出成功却未完成预期检查，返回 JUDGE_ERROR。

### 8.6 默认资源预算

默认每用例墙钟 2 秒、内存 256 MiB、编译 30 秒、整任务墙钟 60 秒、输出 1 MiB、产物 20 MiB、进程数上限 64。RTL 可使用较大预设，但必须明确仿真时间上限与现实墙钟上限，两者不能混同。

题库可请求提高限额，实际生效值为题库请求与用户全局上限中的较小值，并在执行前显示；对于最低资源要求无法满足的题，提示配置不足。程序不能随题库声明无限资源。编译内存独立于用例内存设定，避免合法编译被错误判为用户 MLE。

## 9 AI 环境脚本接口

### 9.1 两层能力

首版优先让 AI 输出环境需求清单，由软件映射到维护过的安装预设，例如“Python + numpy”或“基础 Verilog 仿真”。AI 无需编造安装地址或启动命令。预设包含确定版本、可信来源、校验策略、安装步骤与健康检查。

P1 提供自定义 .envpack.zip，允许 AI 生成 manifest、安装脚本、检查脚本、清理脚本与依赖锁文件。用户把这个包交给环境中心，软件完成校验、计划预览和执行。它与题库协议分离；普通题库导入不会自动触发安装脚本。

### 9.2 Manifest 字段

| 字段 | 规则 |
| --- | --- |
| env_schema_version / env_id / env_version | 协议版本和稳定环境身份 |
| target / architectures | windows-native、linux-container 等目标及 CPU 架构 |
| runtime_capabilities | 可服务的 runtime_ref 与经过检测的特性 |
| dependencies | 依赖 ID、版本约束、来源、文件摘要或镜像摘要 |
| permissions | 网络域名、可写目录、进程执行、系统变更和权限提升 |
| steps | 类型、脚本路径或预设 ID、argv、cwd、timeout、文件摘要 |
| probes | 可执行文件、argv、预期版本及能力检测 |
| cleanup / rollback | 应用私有目录清理或新环境指针回切策略 |
| artifacts / license_notes | 环境锁、安装日志、许可与外部前置要求 |

脚本必须来自包内相对路径，manifest 记录实际 SHA-256；软件对解包结果重新计算。不能使用把网络返回内容直接送进 shell 的安装方式。需要包管理器解析依赖时保存锁文件和来源记录，无法精确锁定的依赖要显示“无法完全复现”。

### 9.3 操作协议

环境接口提供 validate(package)、plan(package, host_info)、apply(plan_id)、probe(env_id)、repair(env_id)、remove(env_id) 六类操作。plan 返回待下载项、写入范围、命令参数、权限、预计资源和需要人工完成的系统步骤。apply 只接受已确认且 hash 未变的 plan_id，不能临时替换执行内容。

脚本输入使用受限 JSON 上下文，包含 task_id、install_root、cache_root、target、参数和下载缓存位置，不传递题库答案、学习数据库或密钥。脚本只能产生日志与结构化结果，不能直接改写软件的环境注册表；软件独立 probe 通过后才能登记 ready。

脚本接口结果含 protocol_version、task_id、status、changed_files、runtime_candidates、warnings、requires_reboot 和 error_code。日志按行 JSON 事件输出，stdout/stderr 都有大小上限。宿主机运行自定义脚本必须展示全文、请求权限和执行范围并获得一次明确确认；相同内容、版本、权限已获信任后可按用户设置复用授权，内容或权限变化重新确认。

### 9.4 安装流程与权限边界

uploaded → validated → planned → approved → installing → verifying → ready。分支为 failed、needs_user_action、needs_reboot、rolled_back。每个阶段都有持久日志，失败后可继续或重试；软件退出后不把未验证完成的环境显示成可用。

默认在软件私有 envs 目录或新容器镜像中安装，不修改系统 Python、不覆盖系统 PATH、不自动关闭安全软件。通用 PowerShell/Bash 脚本一旦在宿主机运行，就具有运行账户的实际权限；manifest 的声明无法单独强制限制它，因此不能称为安全沙箱。任意外来脚本优先在可丢弃容器中构建环境；必须修改宿主机的步骤单独列出，不能自动降级到原生执行。

需要管理员权限、安装 WSL、修改系统组件或重启时，界面说明具体变化并等待用户完成。无法获得权限时保留其他题型和已有环境功能，不反复弹出安装窗口。

### 9.5 可恢复性与环境升级

应用私有环境采用新目录或新镜像安装，验证后切换指针，失败删除新建内容或保留诊断，原环境继续可用。系统级安装和包管理器全局修改可能无法完整回滚，计划页必须标记，并优先改为应用私有安装。

升级不覆盖旧环境锁。正在使用某环境的任务完成前不能删除该环境；没有可复现环境的历史记录仍保留结果与代码。remove 默认只删除软件拥有的目录、镜像和缓存，不能卸载用户原有工具链。

## 10 技术结构与数据模型

### 10.1 建议架构

建议采用 Electron + React + TypeScript 的桌面架构，Monaco 作为代码编辑器，SQLite 保存内容索引和学习记录，本地目录保存附件、代码快照、波形和环境锁。核心业务与界面分离，运行器为独立工作进程或容器，环境安装任务也单独执行。以上是便于个人开发的建议，功能合同不绑定某种框架。

逻辑关系为：桌面界面 → 受控 IPC → 应用服务 → 题库/学习/任务/环境/备份服务 → SQLite 和本地文件；任务服务再调用运行器，AI 服务通过可替换连接器工作。

渲染页面关闭 nodeIntegration、启用 contextIsolation，preload 仅暴露业务白名单。Markdown 和附件视为不可信输入；renderer 不能任意读写文件或启动进程。依赖升级与安全配置需参考 [Electron 官方安全文档](https://www.electronjs.org/docs/latest/tutorial/security)；编辑器能力参考 [Monaco 官方项目](https://microsoft.github.io/monaco-editor/)。

### 10.2 核心实体

| 实体 | 关键字段 | 约束 |
| --- | --- | --- |
| Bank / BankRelease | bank_id、version、hash、import_batch_id | 发布版本可追溯 |
| Question / QuestionRevision | question_id、revision、type、payload、content_hash | 版本不可就地改写 |
| KnowledgePoint / QuestionKnowledge | point_id、parent_id、question_revision_id | 多对多与主知识点标记 |
| Asset | logical_path、sha256、size、storage_path | 摘要校验，引用计数 |
| Session / SessionItem | mode、seed、ordered_question_revision_ids | 续做保持原题序 |
| Draft | question_revision_id、runtime_ref、content、updated_at | 与正式提交分离 |
| Attempt / CaseResult | snapshot、verdict、assisted、test_hash、env_lock_id | 历史不可覆盖 |
| ReviewState / ReviewEvent | due_at、stage、rating、scheduler_version | 当前状态可重建 |
| WrongItem / Bookmark / Note | question_id、reason、collection、content | 用户数据独立 |
| Runtime / RuntimeLock | adapter_version、tool_versions、digest、capabilities | 固定真实运行环境 |
| Job / EnvInstall / ImportBatch | state、progress、logs、error | 中断可恢复 |
| StudyPlan / Task / Backup | scope、schedule、completion、backup_manifest | 可导出和恢复 |

### 10.3 文件目录建议

应用数据目录下使用 db/、banks/、blobs/、drafts/、attempts/、jobs/、envs/、env-locks/、logs/ 和 backups/。内容附件按 hash 去重，运行任务使用独立临时目录；日志保留策略不影响代码、题目和学习记录。

删除题库默认先归档，保留用户笔记与历史快照。永久删除需要列出影响范围；删除附件必须确认无其他题库、笔记或历史记录引用。数据库升级前自动备份，失败停止升级并允许恢复。

### 10.4 应用服务边界

题库服务负责 validate_import、preview_import、commit_import、export_bank 和 revise_question；学习服务负责 start_session、save_draft、submit_answer、get_feedback 和 review_queue；任务服务负责 run_sample、submit_code、cancel_job 和 get_job；环境服务使用第 9 章接口；备份服务提供 create、verify、restore。

所有修改请求有 request_id。正式提交使用幂等键避免重复作答，提交时绑定草稿快照，运行过程中继续编辑不改变已提交代码。恢复备份前停止写入任务并创建恢复前快照。

## 11 异常与非功能要求

### 11.1 常见异常的产品行为

| 场景 | 预期行为 |
| --- | --- |
| AI 返回混入说明或 Markdown 围栏 | 明示可提取候选 JSON，预览后校验，不执行内容 |
| JSON 重复键或截断 | 阻止导入，标记行列与相关字段 |
| 答案引用不存在或题目有歧义 | 前者硬错误；后者标为争议并暂停计入掌握度 |
| 环境工具存在但特性不足 | 标记能力不匹配，显示失败 probe |
| 运行死循环或无限打印 | 按限额终止整个任务，界面可继续使用 |
| 运行中断电或软件崩溃 | 草稿恢复；运行任务标记中断，不伪造分数 |
| AI 不可用或网络失败 | 保留已输入内容，可重试，离线做题继续 |
| 导入或恢复时磁盘不足 | 事务回滚，原题库与记录保持可用 |
| 题库更新后答案改变 | 新 revision 重新评估，旧版记录保持原判分 |
| 系统时区改变 | UTC 历史保留，未来日程按用户确认的时区重算 |

### 11.2 性能与容量目标

首版以 10,000 道题、100,000 条作答记录、单用户电脑为验收基准。冷启动目标 5 秒以内；索引完成后的列表筛选与搜索 P95 在 500 毫秒以内；已缓存客观题判分 P95 在 200 毫秒以内；草稿保存不阻塞输入。

导入上限默认压缩包 100 MiB、解压后 500 MiB、10,000 个文件、单文本文件 10 MiB、最大压缩比 100:1，用户可在受控设置中调整。超出时提示拆包；大文件处理在工作线程执行并显示进度。题目数和引用深度也有限额，避免异常输入卡死界面。

代码运行时间取决于工具链和机器，不把编译下载时间纳入“200 毫秒判分”承诺。性能验收需记录 CPU、内存、磁盘、冷/热缓存与后端类型。

### 11.3 数据与隐私

本地数据库是学习记录的主存储，默认不上传。备份包包含数据库一致性快照、用户题库、附件、笔记、草稿、作答和环境锁，不默认包含大型工具链或下载缓存；恢复后通过锁重新定位或重装工具。

自动备份默认每日一次并在大批量导入、数据库升级和恢复前执行，保留最近 7 个每日版本及最近 4 个每周版本。备份后校验 manifest 和摘要，定期允许用户在新目录试恢复；备份位置应可选其他磁盘。

远程 AI、自动更新和外部链接访问分别配置。日志需脱敏，默认保留 30 天，可主动清理。API Key、不必要的个人路径和环境变量不写入导出文件；无法判断是否敏感的上下文由上传预览明确列出。

### 11.4 可用性

支持键盘完成答题、提交、切题与取消；焦点状态清晰，结果不只靠红绿区分；字体与代码字号可调整，长题干和长日志可折叠。危险操作提供影响说明和撤销/备份入口，普通练习流程不反复弹确认。

## 12 版本交付与验收

### 12.1 开发顺序

里程碑 A 完成桌面壳、数据模型、单选/多选/判断、QBank 导入导出、题库编辑和草稿。验收后就能开始内容积累。

里程碑 B 完成 Python、C/C++、基础 Verilog 适配器、受控执行、样例/提交区分、环境预设安装、日志与失败定位。首版必须包含这一阶段，不能只交付客观题壳。

里程碑 C 完成错题、收藏、笔记、复习、统计、备份恢复和批量异常处理，构成 P0 可日常使用版本。

P1 再增加软件内 AI、填空/主观题、模拟测验、波形内嵌、自定义环境脚本包、更多语言与函数型评测；P2 扩展综合实验、专业 EDA 和多设备同步。排期按实际开发能力估算，不在功能文档中承诺未经评估的固定工期。

### 12.2 P0 验收用例

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| AC01 | 导入有效客观题库 | 题数、选项、答案、解析与知识点全部一致 |
| AC02 | 导入错误引用、重复键、穿越路径 | 精确报错，数据库和现有文件无部分修改 |

| AC05 | 重启并继续练习 | 题序、草稿、语言、计时状态按设计恢复 |
| AC06 | Python、C、C++ 运行并提交 | 样例与正式记录分开，正确解通过，错误解失败 |
| AC07 | Verilog 正确解与已知错误解 | 参考解通过，缺复位等错误解被测试拒绝 |

P1 必须追加环境脚本计划变更校验、权限变更重新确认、安装回切、波形定位、AI 评分来源与数据上传预览的验收。

### 12.3 交付前需要落实的产品决定

本文已给出可直接推进的默认方案。开发启动时需把目标电脑配置、容器后端选择、首批语言工具的实际版本、首批题库范围和是否需要软件内 AI 连接记录到项目配置；这些决定不会改变题库与学习记录分离的基本架构。

## 13 配套文件与使用方式

- qbank.schema.json：QBank 1.0 结构定义，采用 JSON Schema Draft 2020-12。
- examples/demo-bank.json：含单选、多选、判断、填空、简答、Python 编程和 Verilog RTL 的完整内联题库，用于协议演示。

- examples/示例题库说明.md：逐题说明、环境映射、参考解与测试的验证范围。

示例题库用于说明格式，不代表已经完成领域知识审定；软件导入时仍应走完整的校验与发布检查。数字 IC 大纲可从数字逻辑、Verilog、时序逻辑、FSM、FIFO、CDC、STA、体系结构与验证逐步建立；涉及 CDC/STA 的题目需分别设计其判定依据，不能统一套用仿真通过。
