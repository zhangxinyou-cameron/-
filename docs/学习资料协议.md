# LearnPack 1.0

在学习中心导入 JSON，或粘贴 AI 生成的完整 JSON。完整示例见 [learnpack-demo.json](../examples/learnpack-demo.json)，含两章资料和内嵌题库，可直接导入。

根字段：schema_version 固定 "1.0"；id 为稳定小写 ID；title、version（x.y.z）、chapters 必填；description、qbank 可选。不能添加未知字段。

每章字段：id、title、knowledge_points（非空字符串数组）、content_md（Markdown 正文）、question_refs（非空数组）。题目引用为 {bank_id, question_id}，指向当前题库版本；引用必须在软件已导入题库或随包附带的 QBank 中存在。建议一章围绕一个核心知识点，正文讲解、例子与题目目标一致。

限制：单包不超过 8 MiB；1～200 章；正文不超过 500000 字符；全课程累计不超过 1000 个题目引用。重复章节 ID、重复章节内题目引用、缺失引用、未知字段会阻止导入。

qbank 采用现有 QBank 1.0 完整协议，不能自行发明题型或环境 ID。内嵌题库与课程在同一 SQLite 事务中导入；失败不会留下半个课程或半套题库。

同课程 id/version 相同内容可重复导入；同版本不同内容拒绝覆盖。修改发布过的课程需增加 version；题库变更还须遵守 QBank 的 revision/bank_version 规则。题目绑定当前 revision，因此题目升级后会按新版作答重新计算独立通过状态。

正文编辑保存为个人覆盖层，原始导入资料保留；笔记和覆盖层随插件关闭、重启、课程更新及学习备份保存。课程更新或正文编辑后已读标记失效，需重新确认阅读。已读且所有关联题目有当前版本的正式作答，才显示已学完；对错和辅助作答均不影响完成。正式作答包括 AC、WA、CE、RE、TLE、MLE、OLE；样例、ENV_ERROR、JUDGE_ERROR 与 CANCELED 不计入。独立 AC 仍单独表示掌握。已有正式作答记录直接计入，不要求重新答题。

导出课程包含个人编辑的正文，不包含私人笔记和作答；有个人正文覆盖时自动增加导出课程的补丁版本，避免同版本冲突。整体备份可保存笔记、插件开关和学习进度。

## 给 AI 的生成提示词

为知习学习中心生成完整 LearnPack 1.0 JSON 文件。以我的学习目标为范围，按核心知识点组织章节；每章包括学习目标、原理讲解、逐步例子、常见误区、理解检查和对应测试题。资料使用清楚的中文 Markdown，不嵌入 HTML/脚本，不虚构来源。每章填写 id、title、knowledge_points、content_md、question_refs。根包含 schema_version、id、title、version、description、chapters；如新生成题目，根 qbank 内嵌完整 QBank 1.0，并将题目稳定 ID 关联到对应章节。优先一章一个核心知识点，确保每个知识点均有阅读输入与测试输出。现有题库则使用我提供的 bank_id/question_id，不猜不存在的 ID。参考 examples/learnpack-demo.json 和题库协议与示例/qbank.schema.json。输出完整 JSON，不用省略号，不把校验结果写入未定义字段。

## 章节练习衔接（0.4.1）

从阅读器开始章节测试会自动确认当前课程版本已读，并在同一事务内保存带课程/章节来源的练习会话。答题后重新读取正式作答记录，练习页面显示本章进度；只在最后一道题显示下一章入口，并等待本章所有题目作答后启用。末章可返回课程列表。会话来源随重启续做保存。普通题库练习不自动标记课程已读；旧记录也不会被自动改成已读，可手动确认或再次开始章节测试。

阅读器自动将最近章节与主阅读区滚动位置保存在插件自己的 SQLite 元数据中。课程卡片显示已学完章节、已读章节、已作答题数、上次章节和总进度；点击“继续学习”恢复最近位置。总进度为（已读章节数 + 已作答题目引用数）/（章节总数 + 题目引用总数）。同一题出现在多个章节时按各章引用计数。重启、插件开关、备份恢复保留位置；旧版无位置记录时尝试从最近章节会话恢复章节。课程升级保留有效章节，但滚动位置归零，已删除章节回到第一章。阅读位置不随课程导出泄露。
